# 搜比价移动端优先 UI 复检

日期：2026-07-23  
范围：首页、已登录状态、个人中心、扫码备用流程、管理后台。  
视口：Chrome 移动断点模式，截图输出 390 × 844；额外抽查最窄断点，但因 Chrome 最小 CSS 视口限制未作为截图证据。

## 总结

首页移动体验良好，底部导航触控高度为 48px。主要问题不再是全站底栏，而是登录页重复、个人中心默认任务顺序、自动选中数据、扫码首屏被相机占满，以及管理员导航在移动端横向隐藏。

## 步骤

1. 首页 — 良好：主任务明确，搜索与快捷入口在首屏内。
2. 已登录状态 — 较差：同一账号状态渲染两次，退出入口被推到下一屏。
3. 个人中心首屏 — 一般：快速记录占满首屏，商品和门店自动选中第一项。
4. 快速记录操作 — 一般：主操作明确，但三个纵向大按钮增加滚动长度。
5. 价格记录列表 — 一般：单条记录易读，39 条连续渲染形成过长页面。
6. 扫码备用流程 — 一般：手动入口清楚，但需先经过大相机区域；自动识别不可用时路径不够直接。
7. 管理后台 — 较差：介绍与权限占据首屏，管理导航横向滚动且只露出一个入口。

## 优先级

### P0

- 商品、门店数据加载后不要自动选择第一项，保留“请选择”。
- 管理后台把管理区导航改为两列网格或紧凑标签，避免横向隐藏。

### P1

- 个人中心先展示积分、收藏与最近记录，“快速记录”改为折叠区或独立入口。
- 扫码页由用户点击后启动相机；自动识别不可用时优先显示手动输入。
- 合并登录页重复的账号状态。

### P2

- 价格记录默认展示最近 5–10 条，再加载更多。
- 收藏商品、收藏门店改为并排次按钮。
- 首页搜索框和扫码条码输入框补充可访问名称。
- 把页面中的 `h1 → h3` 跳级改为 `h1 → h2`。

## 已确认的优点

- 首页核心 CTA、背景和信息层级适合移动场景。
- 底部导航三项清楚，触控高度达到 48px。
- 价格记录卡片中的商品、门店、时间和价格容易扫读。
- 页面存在“跳到主要内容”链接。

## 限制

- Chrome 可以触发项目的 `max-width: 720px` 移动断点，但无法可靠模拟项目的 `max-width: 390px` CSS 断点，因此未对超窄屏作确定结论。
- 未做屏幕阅读器、200% 缩放、软键盘遮挡和完整键盘导航测试。
- 未保留任何真实摄像头画面。
