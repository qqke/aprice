# 搜比价登录后 UI 审计

审计日期：2026-07-23  
范围：登录状态、首页、个人中心、扫码页、管理员页；窄屏桌面浏览器视口。

## 结论

首页的核心任务表达最清楚；主要问题集中在固定底部导航遮挡内容、个人中心首屏过重、表单自动选择第一项，以及后台首屏没有尽快露出维护工具。

## 步骤与健康度

1. 已登录状态页 — 较差：账号信息重复，固定底部导航横穿内容。
2. 首页 — 良好：扫码主任务明确，但搜索框被底部导航遮住。
3. 个人中心快速记录 — 一般：表单过长，商品和门店自动选择首项，有误录风险。
4. 积分与任务 — 一般：信息完整，但密度高、层级偏重。
5. 个人价格记录 — 良好：商品、时间、门店和价格易扫读；39 条连续展开过长。
6. 扫码备用流程 — 一般：手动输入清楚，但自动启动相机与“自动识别暂不可用”文案冲突。
7. 管理后台 — 较差：介绍、账号和权限占满首屏，真正的管理操作在首屏外。

## 优先修改

### P0

- 给所有移动页面补足固定底栏的安全间距，确保搜索框、按钮、状态和卡片不会被底栏覆盖。
- 商品和门店保持“请选择”状态，不要在数据加载后自动选中第一项。

### P1

- 个人中心默认先展示积分、收藏和最近记录；把“快速记录”折叠或放到明确的“记录价格”入口。
- 后台移除大面积介绍和重复权限卡，顶部只保留紧凑账号状态与管理区导航。
- 扫码页改为用户点击后启动相机；自动识别不可用时直接突出手动输入。

### P2

- 登录状态页合并重复账号卡片，只保留“打开个人页”“切换账号”“退出登录”一组操作。
- 个人价格记录先展示最近 5–10 条，再用“加载更多”展开。
- 商品/门店改为一个可搜索选择器，避免“搜索框 + 下拉框 + 加载更多”的三段操作。

## 可访问性风险

- 首页搜索框和扫码条码输入框在 DOM 中没有可访问名称。
- 页面多处从 `h1` 直接跳到 `h3`。
- 灰色辅助文字、占位符和浅色状态文本需要实际对比度检测。
- 固定底栏遮挡可见内容，也可能影响键盘焦点和放大后的阅读顺序。
